Most issues with KoboldCPP Colab Modded fall into a few common categories: GPU allocation problems, tunnel connectivity, memory limits, and download failures. This page covers the most frequent problems and their solutions so you can get back up and running quickly.

<AccordionGroup>

  <Accordion title="⚠️ Colab did not give you a GPU">
    **Cause:** Colab's free tier enforces GPU usage limits. If you've used a significant amount of GPU compute recently, Colab will decline to allocate a GPU and the notebook will raise an error similar to:

    ```
    ⚠️Colab did not give you a GPU due to usage limits, this can take a few hours before they let you back in.⚠️
    ```

    **Solutions:**

    - **Wait and retry.** GPU availability resets over time. Waiting a few hours (or until the next day) is often enough to get access again.
    - **Use the free web alternative.** [https://lite.koboldai.net](https://lite.koboldai.net) runs KoboldAI directly in your browser with no GPU required. It doesn't expose an API, but it fully supports KoboldAI story saves and character cards.
    - **Subscribe to Colab Pro.** A Colab Pro subscription gives you priority GPU access and higher usage limits, which largely eliminates this issue.
  </Accordion>

  <Accordion title="Cloudflare tunnel URL not appearing">
    **Cause:** Startup takes time — the notebook must download the KoboldCpp binary and your model before the tunnel can be established. It's also possible the Cloudflare tunnel itself failed to connect.

    **Solutions:**

    - **Be patient.** Model downloads can take several minutes depending on file size and network speed. Wait at least **5 minutes** before concluding something is wrong.
    - **Scroll to the very bottom of the cell output.** The tunnel URL is printed last, after all other startup messages. Scroll past download progress bars and initialization logs.
    - **Enable MakeLocalTunnelFallback.** If no URL appears after 5 minutes, check the **MakeLocalTunnelFallback** box in the form and re-run the cell. A `loca.lt` URL will appear in the output along with a password to enter in your browser. The password is printed in the cell output; you can also retrieve it independently from [loca.lt/mytunnelpassword](https://loca.lt/mytunnelpassword).
  </Accordion>

  <Accordion title="Out of memory / model fails to load">
    **Cause:** The model you selected is too large to fit in the available GPU VRAM, or the context size you've set requires more memory than is available.

    **Solutions:**

    - **Reduce ContextSize.** Larger context windows consume a significant amount of VRAM. Try halving your current value (e.g., from 8192 to 4096).
    - **Use a lower quantization.** Switch to a Q4 variant of your model instead of Q6 or Q8. Lower quantizations use less VRAM with a modest quality trade-off.
    - **Switch to a smaller model.** A 7B or 13B model will fit comfortably where a 24B or 34B will not.
    - **Use the L4 notebook.** The L4 GPU provides 24 GB of VRAM — 8 GB more than the T4. See the [L4 Notebook guide](/guides/l4-notebook) for setup instructions.
    - **Set Layers to Auto.** If you've manually set **Layers** to a high number like `999`, try changing it to `Auto` so KoboldCpp can determine the optimal GPU layer count itself.
  </Accordion>

  <Accordion title="Model download fails or is very slow">
    **Cause:** HuggingFace rate limiting, temporary server issues, or poor network conditions between Colab and the model host.

    **Solutions:**

    - **Wait and retry.** HuggingFace occasionally rate-limits download requests, especially for popular models. Re-running the cell after a few minutes usually resolves it.
    - **Check HuggingFace status.** If downloads consistently fail, verify that HuggingFace is accessible and not experiencing an outage.
    - **Note on download speed.** The notebook uses **aria2** for model downloads, which uses parallel connections for faster transfer speeds. If you're still seeing slow speeds, the bottleneck is likely the source server rather than the download method.
    - **Try a different model.** If a specific model URL is consistently failing, try an alternative model or a different quantization variant from the Template dropdown.
  </Accordion>

  <Accordion title="Session disconnects / AI shuts down unexpectedly">
    **Cause:** Google Colab automatically disconnects sessions that appear idle. If the browser tab is hidden or the connection is interrupted, Colab may shut down the runtime. Occasional CAPTCHA challenges can also pause execution.

    **Solutions:**

    - **Keep the Colab tab open and visible.** Colab's idle detection is based on browser activity. Minimizing or closing the tab increases the risk of disconnection.
    - **Solve CAPTCHA prompts promptly.** Colab occasionally shows a CAPTCHA to verify you're a human. Check the tab periodically and solve any that appear to keep the session alive.
    - **Use Colab Pro.** Colab Pro sessions are significantly more tolerant of idle periods and have longer maximum session durations, greatly reducing unexpected disconnections.
  </Accordion>

  <Accordion title="Manual checkboxes override my template selection">
    **Cause:** The loader checkboxes (**LoadTextModel**, **LoadImgModel**, etc.) take priority over the **Template** dropdown. If any loader checkbox is ticked, the notebook uses your manual settings instead of the preset.

    **Solution:** If you want to use a preset template, make sure **all** loader checkboxes are unchecked. Only tick a loader checkbox when you intend to manually configure a custom model load. To return to template-based loading, uncheck everything and re-select your template from the dropdown.
  </Accordion>

  <Accordion title="Disk full / no space left on device">
    **Cause:** Previously downloaded large model files are still on disk from an earlier run. Colab sessions provide approximately 75–100 GB of temporary storage, which can fill quickly with multiple large model files.

    **Solutions:**

    - **Ensure DeleteExistingModels is checked.** This option (enabled by default) deletes all `.gguf`, `.bin`, and `.ggml` files at the start of each run. If it was accidentally unchecked during a previous run, old model files may still be taking up space.
    - **Restart the Colab runtime.** Go to **Runtime → Restart runtime** in the Colab menu. This gives you a completely fresh environment with empty storage. You'll need to re-run the cell after restarting.
  </Accordion>

</AccordionGroup>
